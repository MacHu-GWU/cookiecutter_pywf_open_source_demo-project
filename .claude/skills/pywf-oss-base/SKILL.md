The conventions of the pywf open-source Python library template, shared by every `pywf-oss-*` skill. In all files, `<package>` is the import package directory (the `[project].name` of `pyproject.toml`, with `-` replaced by `_`).

## References

The references are numbered in project-lifecycle order, from setting up the environment to releasing. For a question about one convention, read only the file that covers it.

## Scripts and assets

Run a script from this skill with `python ${CLAUDE_SKILL_DIR}/scripts/<name>.py`. From an invoker, use `python ${CLAUDE_SKILL_DIR}/../pywf-oss-base/scripts/<name>.py`.

| File | What it does |
| :--- | :--- |
| `scripts/check_test_layout.py` | `--project_root .` lists missing, orphan, and mismatched test files. Add `--source <file>` to print the expected test path and module for one file. |
| `scripts/check_one_import_per_line.py` | `--paths <package> tests` lists import statements with more than one name. Add `--fix` to split them, one name per line. |
| `scripts/check_doc_xrefs.py` | `--html_dir docs/build/html` lists `:class:` / `:func:` / `:attr:` ... references that rendered as plain code because their target is missing; Sphinx does not warn about these. Add `--include_api` to scan the API pages too. |
| `scripts/update_skill_index.py` | Regenerates the References index above from each reference's H1 and `description`. Add `--check` to only verify it. Run it after adding, renaming, or re-describing a reference. |
| `assets/raw-rst-cell.json` | A copy-ready raw reStructuredText notebook cell. |
| `assets/notebook-page-template.ipynb` | A minimal notebook docs page: raw title cell, intro, code cell, cross-reference cell. |

## Which skill to use

Each action skill does one job and loads this base by itself. When the job is unclear, or when the question is about a convention rather than an action, stay in this base: read the reference that covers it, then name the skill that fits.

| Skill | Use it when | Example request | Reads from this base |
| :--- | :--- | :--- | :--- |
| `pywf-oss-setup-machine` | A new machine must be prepared, a token rotated, or a task fails because a tool or token is missing. | "set up my new MacBook" | `00-machine-setup.md`, `08-secrets.md` |
| `pywf-oss-setup-repo` | A repo freshly generated from the template must go live on GitHub, Codecov, and Read the Docs. The user must invoke it by hand. | "put this new repo online" | `09-ci-and-hosting.md`, `00-machine-setup.md`, `01-toolchain.md` |
| `pywf-oss-add-module` | A new module, subpackage, or feature area must be created, with its test file and its `api.py` export. | "add a `core/copy.py` module" | `02-repo-layout.md`, `03-code-style.md`, `04-testing.md`, `scripts/check_test_layout.py` |
| `pywf-oss-write-test` | An existing module needs tests, more coverage, or fixed tests. | "cover `core/copy.py` to 100%" | `04-testing.md`, `03-code-style.md`, `scripts/check_test_layout.py` |
| `pywf-oss-write-doc` | A docs page, guide, tutorial, or notebook must be written or fixed. | "write a quick-start page" | `05-docs-sphinx.md`, `06-docs-sphinx-design.md`, `07-docs-notebook.md`, `assets/*`, `scripts/check_doc_xrefs.py` |
| `pywf-oss-changelog` | The next version's release notes in `release-history.rst` must be written from git history. | "update the changelog" | `10-release.md` |
| `pywf-oss-release` | A version must be bumped, published to PyPI, and tagged on GitHub. The user must invoke it by hand. | "release 1.2.0" | `10-release.md`, `01-toolchain.md`, `08-secrets.md`, `09-ci-and-hosting.md` |
| `pywf-oss-write-pypi-skill` | After a release, to generate an Agent Skill documenting this library's public API for other projects. The user must invoke it by hand. | "make a skill for this library" | `02-repo-layout.md` (section 2), `01-toolchain.md` (section 5) |
| `pywf-oss-fix-ci` | GitHub Actions, the Codecov upload, or the Read the Docs build is red, or a Python version must be added or dropped. | "CI fails on Windows" | `09-ci-and-hosting.md`, `01-toolchain.md`, `12-dependency-upgrades.md` |
| `pywf-oss-upgrade-deps` | Dependencies must be upgraded, an upgrade judged, or an unmaintained package replaced. | "is pytest 9 worth it?" | `12-dependency-upgrades.md`, `01-toolchain.md`, `scripts/check_doc_xrefs.py` |
| `pywf-oss-audit` | A repo must be checked against these conventions, for example an older repo being brought up to the current template. It reports only. | "audit this repo" | all references, all three `check_*` scripts |

The skills are listed in project-lifecycle order. The order in which they usually run, and what each hands to the next, is in `references/11-skill-family-workflow.md`.
