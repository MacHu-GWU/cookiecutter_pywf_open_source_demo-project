# Documentation: Sphinx, reStructuredText, furo, docfly

The docs are built with Sphinx, the furo theme, and nbsphinx from `docs/source/`, and hosted on Read the Docs. Pages are reStructuredText (`.rst`) or Jupyter notebooks (`.ipynb`; see `docs-notebook.md`). The API reference is generated by docfly.

---

## 1. Page tree

```text
docs/source/
├── conf.py                     # Sphinx config; also runs docfly's API generator
├── index.rst                   # home: includes README.rst and AUTHORS.rst, then .. autotoctree::
├── release-history.rst         # .. include:: ../../release-history.rst
├── 01-Getting-Started/
│   └── index.rst               # or index.ipynb
├── 02-Some-Topic/
│   ├── index.ipynb
│   └── images/                 # assets live next to the page that uses them
├── 99-Maintainer-Guide/        # for maintainers, not users
│   ├── index.rst
│   └── 01-Project-Overview/index.rst
├── api/                        # GENERATED by docfly, committed, never hand-edited
└── _static/                    # css, js, logo, favicon, .custom-style.rst
```

- **One folder per page**. The page itself is that folder's `index.rst` or `index.ipynb`.
- Folder names are `NN-Title-In-Kebab-Case`. The two-digit prefix sets the order; the rest is ASCII, with no spaces.
- `.. autotoctree::` (from `docfly.directives`) builds the table of contents from the child folders. It reads each child's `index` file and uses that page's title. You never maintain a `.. toctree::` list by hand. To add a page, create the folder and its `index` file.
- Order user pages by how often readers need them. Reserve `99-Maintainer-Guide/` for maintainer docs.

## 2. reStructuredText conventions

Heading underlines are exactly **78 characters**, at three levels:

```rst
Page Title
==============================================================================

Section
------------------------------------------------------------------------------

Subsection
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
```

- Give a page a label right above its title when other pages link to it. Labels are unique across the whole project, in kebab-case:

  ```rst
  .. _getting-started:

  Getting Started
  ==============================================================================
  ```

- Inline code uses double backticks: ``` ``code`` ```. Code blocks use `.. code-block:: python`.
- External links use `` `text <https://...>`_ ``.
- Use admonitions (`.. note::`, `.. warning::`) sparingly.

---

## 3. Cross-references

| Target | Syntax |
| :--- | :--- |
| A labeled section or page | ``:ref:`getting-started` `` or ``:ref:`custom text <getting-started>` `` |
| A class / function / method / module | ``:class:`<package>.core.S3Path` ``, ``:func:`<package>.utils.chunked` ``, ``:meth:`<package>.core.S3Path.read_text` ``, ``:mod:`<package>.core` `` |
| Show only the last name | ``:class:`~<package>.core.S3Path` `` renders as `S3Path` |
| Python standard library | ``:class:`pathlib.Path` `` (through intersphinx) |
| Another doc file | ``:doc:`../02-Some-Topic/index` `` |

Reference API objects by their **defining** module, the one docfly documents, not by the `api.py` re-export path.

## 4. API reference (docfly)

- `conf.py` runs `docfly.ApiDocGenerator(...).fly()` on every build. It writes one `.rst` file per module into `docs/source/api/`, ignoring `docs`, `tests`, `vendor`, and `paths`.
- To hide another module from the API docs, add it to `ignore_patterns` in `conf.py`.
- docfly uses `.. automodule:: ... :members:`, which **skips names with no docstring**. Every public name needs at least a one-line docstring, or it is missing from the API page, and every `:func:` / `:class:` reference to it renders as plain text instead of a link.
- The API pages come from docstrings. To improve them, edit the docstrings (see `code-style.md`), not the generated `.rst` files.

---

## 5. Other machinery

- `rst_prolog` includes `_static/.custom-style.rst`, which holds the custom roles and styles available on every page.
- `sphinx-jinja` receives `doc_data` from `<package>/docs/__init__.py`. Use it with `.. jinja:: doc_data` when a page must render data from code.
- Other extensions are enabled too: `sphinx-copybutton`, `sphinx-design` (grids, cards, tabs), and `sphinx.ext.viewcode`.

---

## 6. Build and check

```bash
mise run build-doc   # clean build into docs/build/html
mise run view-doc    # open it
```

A doc change is done when `build-doc` finishes with no new warnings, and the new page shows up in the sidebar with the right title and order.
