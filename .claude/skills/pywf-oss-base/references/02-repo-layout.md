# Repository Layout

What each file and folder is for, which ones are special, and which ones are generated.

---

## 1. Tree

```text
<project>-project/
├── <package>/                 # the importable package
│   ├── __init__.py            # minimal; may re-export metadata from _version.py
│   ├── api.py                 # THE public API (see section 2)
│   ├── paths.py               # PathEnum: every project path as an absolute Path
│   ├── _version.py            # optional: __version__ and metadata, must match pyproject.toml
│   ├── cli.py                 # optional: python-fire CLI (see 01-toolchain.md)
│   ├── <module>.py            # normal modules
│   ├── _<module>.py           # private modules: importable inside the package, never exported by api.py
│   ├── <subpackage>/          # each subpackage may have its own api.py
│   ├── vendor/                # third-party code copied in verbatim
│   ├── tests/                 # test HELPERS shipped with the source (run_cov_test, fixtures)
│   └── docs/                  # doc_data for sphinx-jinja
├── tests/                     # unit tests, mirroring <package>/ (see 04-testing.md)
├── tests_int/                 # optional: integration tests (real external services)
├── tests_load/                # optional: load tests
├── docs/source/               # Sphinx source (see 05-docs-sphinx.md)
├── .mise/tasks/*.py           # Python scripts behind mise tasks
├── .claude/                   # Claude Code settings, skills, and launch.json (docs preview server)
├── .github/workflows/main.yml # CI
├── pyproject.toml             # metadata, dependencies, ruff config
├── mise.toml                  # tools, tasks, env vars
├── uv.lock                    # generated
├── requirements*.txt          # generated by `mise run export`
├── .coveragerc / codecov.yml  # coverage config
├── .readthedocs.yml           # Read the Docs build
├── README.rst                 # short: what, install, a few examples, links
├── release-history.rst        # changelog (see 10-release.md)
├── AUTHORS.rst / LICENSE.txt
└── CLAUDE.md                  # project guide for AI (template block + project block)
```

Generated outputs, never edited and never committed unless noted: `htmlcov/`, `docs/build/`, `dist/`, `build/`, `tmp/`, `*.egg-info`. `docs/source/api/` is generated on every docs build **and is committed**.

## 2. `api.py`: the public API

- Users import only through `api.py`. There are two canonical forms:

  ```python
  from <package>.api import X
  import <package>.api as <package>  # then <package>.X
  ```

- `api.py` contains only re-exports, one name per line, using relative imports:

  ```python
  # -*- coding: utf-8 -*-

  from .core import S3Path
  from .core import S3Client
  from . import exc
  ```

- If a subpackage is a coherent unit, give it its own `<subpackage>/api.py` and expose it from the top-level API as a module: `from .better_client import api as better_client`.
- Anything not in `api.py` is internal and may change in any release. Never export a `_private` module or name.
- Adding a name to `api.py` is a feature; removing or renaming one is a breaking change. Record both in `release-history.rst`.
- `api.py` has a test, `tests/test_api.py`, that touches every exported name, so a broken re-export fails CI.

---

## 3. `paths.py`: absolute paths only

- `PathEnum` lists every directory and file the project code or tests need, built from `Path(__file__)`. Nothing depends on the current working directory.
- Use `from .paths import path_enum`, then `path_enum.dir_project_root`, `path_enum.dir_htmlcov`, and so on.
- Need a new path? Add an attribute to `PathEnum`. Do not build paths inline. Use `dir_` and `path_` prefixes for directories and files.
- `paths.py` is excluded from coverage and from the API docs.

---

## 4. `vendor/`: copied third-party code

- Small, single-file utilities copied from elsewhere (for example `pytest_cov_helper.py`) so the package does not take a dependency for them.
- `vendor/` is excluded from ruff, coverage, and the API docs. Do not restyle it. Update it only by copying a newer upstream version.

---

## 5. `<package>/tests/`: test helpers that ship with the code

- These are helpers, not tests: `run_cov_test`, `run_unit_test`, shared fixtures, and mock setup. They live in the package so that test files can `from <package>.tests import run_cov_test`.
- They are excluded from the wheel (`[tool.setuptools.packages.find] exclude`), from coverage, and from the API docs.
- The tests themselves live in the top-level `tests/` folder.

---

## 6. `<package>/docs/`: data for the docs

- `doc_data` is a dict passed to sphinx-jinja templates in the docs. The folder is excluded from the wheel, coverage, and the API docs.

---

## 7. Version and metadata

- `pyproject.toml` `[project].version` is the single source of truth.
- If the package has `_version.py`, its `__version__` must equal the `pyproject.toml` version. Change both together.
