# Documentation: Sphinx, reStructuredText, furo, docfly

The docs are built with Sphinx, the furo theme, and nbsphinx from `docs/source/`, and hosted on Read the Docs. Pages are reStructuredText (`.rst`) or Jupyter notebooks (`.ipynb`; see `07-docs-notebook.md`). The API reference is generated by docfly.

---

## 1. Page tree

```text
docs/source/
├── conf.py                     # Sphinx config; also runs docfly's API generator
├── index.rst                   # home: includes README.rst and AUTHORS.rst, then .. autotoctree::
├── release-history.rst         # .. include:: ../../release-history.rst
├── 01-Getting-Started/
│   └── index.rst               # or index.ipynb
├── 02-Some-Topic/
│   ├── index.ipynb
│   └── images/                 # assets live next to the page that uses them
├── api/                        # GENERATED by docfly, committed, never hand-edited
└── _static/                    # css, js, logo, favicon, .custom-style.rst
```

- **One folder per page**. The page itself is that folder's `index.rst` or `index.ipynb`.
- Folder names are `NN-Title-In-Kebab-Case`. The two-digit prefix sets the order; the rest is ASCII, with no spaces.
- `.. autotoctree::` (from `docfly.directives`) builds the table of contents from the child folders. It reads each child's `index` file and uses that page's title. You never maintain a `.. toctree::` list by hand. To add a page, create the folder and its `index` file.
- Order user pages by how often readers need them. Template conventions are not docs pages: they live in the `pywf-oss-*` skills.

## 2. reStructuredText conventions

Heading underlines are exactly **78 characters**, at three levels:

```rst
Page Title
==============================================================================

Section
------------------------------------------------------------------------------

Subsection
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
```

- Give a page a label right above its title when other pages link to it. Labels are unique across the whole project, in kebab-case:

  ```rst
  .. _getting-started:

  Getting Started
  ==============================================================================
  ```

- Inline code uses double backticks: ``` ``code`` ```. Code blocks use `.. code-block:: python`.
- External links use `` `text <https://...>`_ ``.
- Use admonitions (`.. note::`, `.. warning::`) sparingly.

## 3. Cross-references

These roles work the same way in `.rst` pages, in raw reST cells of notebooks, and in docstrings. A working page that uses every form below is `docs/source/01-Sample-RestructuredText-Document/index.rst`. Copy from it.

### 3.1 Python objects

Always write the **full dotted path from the defining module**: the module docfly documents, not the `api.py` re-export. Then pick the display form that reads best in the sentence:

| Target | Full path, displayed as written | Preferred display form | Renders as |
| :--- | :--- | :--- | :--- |
| Module | ``:mod:`<package>.module_name` `` | (same) | `<package>.module_name` |
| Class | ``:class:`<package>.module_name.ClassName` `` | ``:class:`~<package>.module_name.ClassName` `` | `ClassName` |
| Method | ``:meth:`<package>.module_name.ClassName.method_name` `` | ``:meth:`ClassName.method_name <<package>.module_name.ClassName.method_name>` `` | `ClassName.method_name()` |
| Function | ``:func:`<package>.module_name.func_name` `` | ``:func:`~<package>.module_name.func_name` `` | `func_name()` |
| Function, with its module | | ``:func:`module_name.func_name <<package>.module_name.func_name>` `` | `module_name.func_name()` |
| Module-level constant | ``:attr:`<package>.module_name.CONSTANT_NAME` `` | ``:attr:`~<package>.module_name.CONSTANT_NAME` `` | `CONSTANT_NAME` |
| Class attribute or property | ``:attr:`<package>.module_name.ClassName.attr_name` `` | ``:attr:`ClassName.attr_name <<package>.module_name.ClassName.attr_name>` `` | `ClassName.attr_name` |

Rules:

- `~` keeps only the last name. Use it when the context already makes the module obvious.
- `title <target>` sets the displayed text to anything you like. For a method, use `ClassName.method_name`, because a bare `method_name` loses its class.
- Use the role that matches the object type: `:meth:` for methods, `:func:` for functions, `:attr:` for constants and attributes. Sphinx may still resolve a mismatched role, but the rendering (for example, trailing `()`) will be wrong.
- A target resolves only if the object is on an API page. That means it needs a docstring. A module-level constant needs a `#:` doc comment above it, and a dataclass, pydantic, or ORM field needs a trailing `#:` comment on its line (see section 4). An unresolved target renders as plain code, not a link, and Sphinx gives **no warning**. So after building, run `python ${CLAUDE_SKILL_DIR}/../pywf-oss-base/scripts/check_doc_xrefs.py`; it lists every reference that is not a link.

### 3.2 Pages, sections, and the standard library

| Target | Syntax |
| :--- | :--- |
| A labeled section or page | ``:ref:`getting-started` `` or ``:ref:`custom text <getting-started>` `` |
| Another doc file | ``:doc:`../03-Some-Topic/index` `` (relative to the current page), or ``:doc:`/03-Some-Topic/index` `` (from `docs/source/`) |
| Python standard library (through intersphinx) | ``:class:`pathlib.Path` ``, ``:func:`json.dumps` `` |

## 4. API reference (docfly)

- `conf.py` runs `docfly.ApiDocGenerator(...).fly()` on every build. It writes one `.rst` file per module into `docs/source/api/`, ignoring `docs`, `tests`, `vendor`, and `paths`.
- To hide another module from the API docs, add it to `ignore_patterns` in `conf.py`.
- docfly uses `.. automodule:: ... :members:`, which **skips names with no docstring**. Every public name needs at least a one-line docstring, or it is missing from the API page, and every reference to it renders as plain text instead of a link.
- A module-level constant or a class field is documented only by a `#:` doc comment, either on the line above or trailing on the same line:

  ```python
  #: Greeting used when no name is given.
  DEFAULT_NAME = "World"


  class Greeter:
      # fmt: off
      greeting: str = dataclasses.field(default="Hello")  #: Word put in front of the name.
      # fmt: on
  ```
- The API pages come from docstrings. To improve them, edit the docstrings (see `03-code-style.md`), not the generated `.rst` files.

## 5. Other machinery

- `rst_prolog` includes `_static/.custom-style.rst`, which holds the custom roles and styles available on every page.
- `sphinx-jinja` receives `doc_data` from `<package>/docs/__init__.py`. Use it with `.. jinja:: doc_data` when a page must render data from code.
- Other extensions are enabled too: `sphinx-copybutton`, `sphinx.ext.viewcode`, and `sphinx-design` (grids, cards, tabs, dropdowns, badges, buttons; see `06-docs-sphinx-design.md`).

## 6. Build and check

```bash
mise run build-doc   # clean build into docs/build/html
mise run view-doc    # open it
```

A doc change is done when `build-doc` finishes with no new warnings, and the new page shows up in the sidebar with the right title and order.

**Visual check by an AI.** In the Claude desktop app, open the built site with the browser pane's `preview_start` and the `docs-html` configuration in `.claude/launch.json`. It serves `docs/build/html` over HTTP on the port the pane assigns. Do not open the files with `file://`: the pane then shows a static snapshot without CSS, so widgets and the theme cannot be judged. Humans keep using `mise run view-doc`. Their browser loads CSS from `file://` just fine.
