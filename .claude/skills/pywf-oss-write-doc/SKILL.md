Write or update one docs page under `docs/source/`, so that it builds cleanly, appears in the sidebar, and links correctly to the API reference and other pages.

Read ../pywf-oss-base/SKILL.md, then:
- ../pywf-oss-base/references/05-docs-sphinx.md
- ../pywf-oss-base/references/06-docs-sphinx-design.md (only when the page needs layout or widgets: cards, tabs, dropdowns, badges, buttons)
- ../pywf-oss-base/references/07-docs-notebook.md (only for notebook pages)

Templates: ../pywf-oss-base/assets/notebook-page-template.ipynb and ../pywf-oss-base/assets/raw-rst-cell.json.

## Steps

1. **Pick the format and place.**
   - Use a notebook for runnable usage guides, and `.rst` for concepts and design notes. If the user did not say, choose and state your choice.
   - Choose the `NN-Title` folder so the page lands at the right position in the sidebar. List the existing folders first.
2. **Gather facts.** Read the public API (`api.py`) and the source docstrings of what you document. Examples import from `<package>.api`, as users would.
3. **Write.**
   - Give the page a unique kebab-case label and a title with a 78-character underline (in a notebook, both go in a raw reST cell).
   - Use `:class:` / `:func:` / `:meth:` for API names, by their defining module, and `:ref:` for other pages. In notebooks, every role and directive goes in a raw reST cell.
   - Edit notebooks with `NotebookEdit` or `nbformat`.
4. **Run notebooks.** `.venv/bin/jupyter nbconvert --to notebook --execute --inplace <path>`. Every cell must succeed, and the outputs are committed.
5. **Build and check.** Run `mise run build-doc` and confirm all of the following:
   - no new warnings,
   - no undefined labels,
   - the page is in the sidebar with the right title,
   - API references render as links. Plain-text code means the target has no docstring or the path is wrong.

## Boundaries

- Never edit `docs/source/api/` (generated by docfly). To improve API pages, improve the docstrings, and say so.
- Keep `README.rst` short. Long material goes in a docs page that the README links to.
